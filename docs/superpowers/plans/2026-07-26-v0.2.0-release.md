# Resource Safe Execution v0.2.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the merged distribution work as a version-consistent, checksum-audited `v0.2.0` GitHub release.

**Architecture:** Keep the canonical nine-file skill payload and its checksum manifests unchanged. Enforce the release contract in one focused test module, update only public version surfaces and release notes, then gate the permanent tag on local validation and six-job CI.

**Tech Stack:** Markdown, JSON, Python 3.10+ `unittest`, Git, GitHub CLI, skills CLI 1.5.20

## Global Constraints

- Preserve `v0.1.0`, `skills/resource-safe-execution`, `skill-manifest.json`, and `SHA256SUMS` byte-for-byte.
- Use `v0.2.0` for README release pins, Codex metadata, Claude metadata, Git tag, and GitHub release.
- Do not add physical macOS/Linux or proprietary client-runtime claims.
- Run tests sequentially under the low-impact resource profile.
- Do not create the tag until local validation and all six CI jobs pass.

- [ ] **Step 1: Write the failing tests**

```python
import json
import unittest
from pathlib import Path


ROOT = Path(__file__).resolve().parents[1]
VERSION = "0.2.0"
TAG = f"v{VERSION}"


class ReleaseReadinessTests(unittest.TestCase):
    def test_public_version_surfaces_match(self):
        codex = json.loads(
            (ROOT / ".codex-plugin" / "plugin.json").read_text(encoding="utf-8")
        )
        claude = json.loads(
            (ROOT / ".claude-plugin" / "plugin.json").read_text(encoding="utf-8")
        )
        marketplace = json.loads(
            (ROOT / ".claude-plugin" / "marketplace.json").read_text(
                encoding="utf-8"
            )
        )
        self.assertEqual(codex["version"], VERSION)
        self.assertEqual(claude["version"], VERSION)
        self.assertEqual(marketplace["plugins"][0]["version"], VERSION)

    def test_readme_pins_current_release(self):
        readme = (ROOT / "README.md").read_text(encoding="utf-8")
        self.assertIn(
            f"github.com/pntech20/resource-safe-execution/tree/{TAG}/"
            "skills/resource-safe-execution",
            readme,
        )
        self.assertIn(f"The current release is `{TAG}`.", readme)
        self.assertNotIn("The release is `v0.1.0`.", readme)

    def test_release_notes_define_scope_and_install(self):
        notes = (ROOT / "docs" / "releases" / f"{TAG}.md").read_text(
            encoding="utf-8"
        )
        self.assertIn("# Resource Safe Execution v0.2.0", notes)
        self.assertIn("packaging and distribution release", notes)
        self.assertIn("canonical nine-file skill payload is unchanged", notes)
        self.assertIn("No new client-runtime compatibility claim", notes)
        self.assertIn(
            f"github.com/pntech20/resource-safe-execution/tree/{TAG}/"
            "skills/resource-safe-execution",
            notes,
        )


if __name__ == "__main__":
    unittest.main()
```

- [ ] **Step 4: Create and publish the release**

Run:

```powershell
git fetch origin main
$mergeCommitSha = gh pr view --repo pntech20/resource-safe-execution 2 --json mergeCommit --jq '.mergeCommit.oid'
$reviewedTreeSha = git rev-parse "HEAD^{tree}"
$mergeTreeSha = git rev-parse "$mergeCommitSha^{tree}"
if (-not $mergeCommitSha -or $mergeTreeSha -ne $reviewedTreeSha) {
    throw "Merged release tree does not match the reviewed branch tree"
}
git merge-base --is-ancestor $mergeCommitSha origin/main
if ($LASTEXITCODE -ne 0) {
    throw "Merged release commit is not contained in origin/main"
}
git tag -a v0.2.0 $mergeCommitSha -m "Resource Safe Execution v0.2.0"
git push origin v0.2.0
gh release create v0.2.0 skill-manifest.json SHA256SUMS --repo pntech20/resource-safe-execution --title "Resource Safe Execution v0.2.0" --notes-file docs/releases/v0.2.0.md --verify-tag
```

Expected: the reviewed branch tree and squash-merge tree are identical, the
tag resolves to PR #2's immutable merge commit, and the release exposes both
checksum assets.
