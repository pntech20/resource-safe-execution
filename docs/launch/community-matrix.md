## 30-day sequence

1. **Days 1–3:** finish repository metadata, live listing, assets, and policy links.
2. **Days 4–7:** invite permissioned beta testers through existing relationships and fix onboarding defects.
3. **Days 8–14:** publish a human-reviewed article and native X/LinkedIn demos only through the account holder.
4. **Days 15–21:** use tailored, rule-eligible community posts; keep the maker available for Show HN.
5. **Days 22–30:** publish verified follow-up evidence and approach only directories whose thresholds are met.

## Operating stop rules

After 500 qualified repository visits, if fewer than 150 become recorded
skills.sh installs, pause promotion and repair the headline, demo, or install
path before a small beta retest.

Any safety or compatibility defect pauses promotion immediately. Publish its
scope, add a reproducible test, fix it, run the full suite, update the evidence,
and resume only after verification.
